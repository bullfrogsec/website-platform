What is an AI agent harness, and why is it a security risk?

You probably know the models from OpenAI, Anthropic and Google: you type a question, and they write an answer. Text is all a model can produce. An agent harness is what lets it act. Here is how a harness works, how it can be manipulated, and how agents are being secured.

Mathieu Larose, CTO & Co-Founder
November 2026

You have probably used a model from OpenAI, Anthropic or Google, through ChatGPT, Claude or Gemini. You type a question, and it writes an answer. That is all a model, or large language model (LLM), can do: it reads text and writes text. On its own, it cannot open a file, run a program or send an email.

An agent harness is the program that wraps the model so it can act. It gives the model tools, such as reading files or sending email, and runs them whenever the model asks. It runs on your computer or server, with your access.

Put together: agent = model + harness. The model decides what to do next, and the harness does it. Claude Code and Codex are well-known harnesses.

The harness works in a loop. It asks the model for the next step, carries it out, and asks again, until the task is done.

What the harness does

The harness is everything in an agent that isn't the model:

  • It holds the tools. Each tool is something the agent can do: read a file, send an email, search the web, run a command.
  • It builds the context. Before each step, it sends the model your task, the list of tools and everything that has happened so far.
  • It runs the loop. The model replies with a tool call, a short structured request to use one tool. The harness runs it, adds the result to the context and asks again, until the model says the task is done.
  • It applies the rules. It decides which actions run on their own and which need a person to approve them.

It does all of this with your access: your files, your accounts, your network.

How the harness gets manipulated

The harness does what the model asks, and the model decides from the context. To the model, the context is one long block of text: your request, the text of a file and the body of an email all arrive the same way. It cannot reliably tell which parts are instructions from you. If an email it reads says "also do this", it may ask the harness to do it. This is called prompt injection. It works like phishing aimed at the agent.

A person reading that email would have found the note strange. The model may or may not: it reads the note in the same block of text as your request. The harness doesn't judge at all. It runs whatever tool call the model sends, as long as its rules allow it, and forwarding an email is an ordinary action. The attacker needed only your email address, and got an email that only you could read.

Can't the AI providers fix prompt injection?

They are trying. Models are trained to resist it, and attacks succeed less often than they used to. But none of the providers says the problem is solved:

[…] protection in the model layer will never be 100% effective, which is why it can't stand alone.

— Anthropic, May 2026

Prompt injection, much like scams and social engineering on the web, is unlikely to ever be fully "solved."

— OpenAI, December 2025

Even with the state-of-the-art mechanisms above, it is still possible that some injections might evade these defenses.

— Microsoft, July 2025

In short

An AI agent is a model that decides and a harness that acts, with your access. The model can be misled by anything it reads, and the providers say that won't fully go away. So treat an agent like any powerful account: give it only what its task needs, and check what it actually does, especially what leaves your machine.

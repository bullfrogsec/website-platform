Agents are your new attack surface

What makes them useful is exactly what makes them dangerous. You need to easily control what they send out.

They have access to your data

Whatever the agent can read, it can send.

They have access to the internet

The services your agents need every day are the same ones your data can leave through.

They act on untrusted input

A web page, an issue or a dependency can carry instructions the agent will follow.

Bullfrog allows the request, not the domain

One background service on each machine. It reads each request before it gets out and blocks anything that machine's policy does not allow.

1

Install it on the Linux machines you already have

Installed like any other package, on-prem or in any cloud. Nothing to re-route.

apt install bullfrog
2

Give each machine its own policy

Write rules on the domain, method, path and body of a request, and manage them from the Bullfrog control plane.
3

Every request is judged on the machine

Only allowed requests leave, and every verdict lands in the log. The control plane is never in the path of your traffic, so your requests stay on your machine.

Example policy

GET registry.npmjs.org/*allowinstall packages, never publish
GET github.com/*allowread any repo
POST github.com/<your-org>/*allowpush to your own org only
POST api.github.com/repos/<your-org>/*allowopen issues and pull requests in your own org only
everything elseblockno sending data anywhere else

A firewall that allows github.com allows a push to any repo, and one that allows registry.npmjs.org allows publishing a package. This policy does not.

Built for the way agents run

Per request, not per domain

Decide on the method, path and body of each HTTPS request, so shared services like GitHub stay usable without becoming a way out.

No CA, no proxy

No certificates to create, distribute or rotate, and no trust store to configure per tool. Tools that pin their certificate are covered.

A policy per machine

Allowing a site for one machine does not open it for every machine that shares a rule.

Covers every container

Code running in containers is covered, with nothing baked into your images.

Knows which process asked

Every verdict names the process that made the request, not just an IP and a port.

Payloads never leave your machine

Enforcement is local. Nothing is decrypted elsewhere, and there is no extra service in the path that can go down.

Every control you have today has a hole in it

Too coarse

VPC, security groups, firewall

  • Allow github.com, and you allow a push to any repo
  • Allow a site for one machine, and every machine sharing the rule can reach it

Too invasive

Man-in-the-middle proxy

  • Your own CA on every machine and inside every tool
  • Pinned certificates and containers break, or bypass it

An AI guarding an AI

LLM guardrails, tool-call classifiers

  • A model guessing whether a call looks malicious
  • Open to the same prompt injection as the model it guards
